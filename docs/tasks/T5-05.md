# T5-05 裏のウィンドウの枠を描き直す

- **状態**: 完了（再表示要求は作業領域だけ。枠はマネージャの仕事）
- **委譲**: ○

- 依存: T5-01（WM）・T4-11
- 触った: `src/subsystems/window/winman.c` の `expose`

**枠を描くのはマネージャである。** 持ち主に再表示を頼んでも
（`wsv_req_dsp`）、描き直されるのは作業領域だけで、枠・タイトルバー・
スクロールバー・四隅のハンドルは誰も描かない。重なったウィンドウを
拡大縮小すると、**裏のウィンドウの枠が消えたままになっていた**。

`expose` を次の形に直した。

1. 机 (BLACK50) で塗るのは**本当に何も無い所だけ**にする。下に
   ウィンドウがある区画は前置長方形リストで外す（仕様 §2.2.4）。
   机で塗ってから描き直すと、そこが一度消えてから戻る
2. 当たったウィンドウを**奥から手前へ** `redraw`（枠＋作業領域の背景）
3. 中身は従来どおり持ち主に `wsv_req_dsp` で頼む

作業領域の背景もマネージャが塗る。塗らないと、動いたウィンドウの
古い画素が持ち主の描き直しまで残る。

- **既知の制限**
  - 前置長方形リストは 16 個まで（`DP_MAX_FORE`）。超えた分は机で
    塗られてから描き直されるので、絵は合うが一瞬ちらつく
  - **「同じ点を 2 回書かない」こと自体は外から観測できない。**
    検査できるのは結果の絵だけである
  - 根本的には**ウィンドウごとのバックバッファ (E2)** で、
    再表示要求に頼らずマネージャが合成するのが筋
- **受入条件**（通過）
  - 手前のウィンドウで裏のタイトルバーを隠し、どかすと**白一色の
    タイトルバーが戻る**（机の 50% 柄と見分けられる）
