# T2-19 ユーザ特権 (EL0) とシステムコール

- **状態**: 完了（svc 経由。ユーザポインタを検める）
- **委譲**: ✗

- 依存: MMU (T2-10)・プロセス §1.1・例外ベクタ (T1-03)
- 触った: `include/btron/syscall.h` ＋ `src/kernel/core/syscall.c`
  ＋ `vectors.S`（Lower EL の同期例外）＋ `context.S`
  （`btron_user_trampoline`）＋ `context.c`（`hal_ctx_init_user`）
  ＋ `task.c`（`knl_sta_tsk_user`）＋ `src/lib/sys/`（ユーザ側スタブ）

**仕様はここを規定していない。** システムコールを関数として定義して
いるだけで、どう特権境界を越えるかは書いていない（CPU ごとに違うので
当然）。本OS の約束は arm64 で `x8 = 番号 / x0〜x5 = 引数 / svc #0`。

**ユーザから来たポインタは必ず検める (`usr_ok`)。** ここが保護の要で、
カーネルの番地を渡されたら自分の権限で読み書きしてしまう。PAN
（特権アクセス禁止）には頼らない —— PAN は「触れない」だけで
「どこを触ろうとしたか」を教えてくれず、誤りが例外になって落ちるだけに
なる。明示的に範囲と写像を見る方を選んだ。

**配りの表は 1 本ずつ書いた。** 関数ポインタの配列にすれば短くなるが、
引数の型と個数が呼び出しごとに違うので、それをやると「どのポインタを
検めるべきか」が表から消える。検めを忘れた 1 本がカーネル全体の穴になる。

- **受入条件**（すべて通過）
  - EL0 のプログラムからシステムコールが届く
  - **カーネルの番地を渡すと `ER_ADR` で断られる**
  - システムコールを通さずカーネル番地を読んだプロセスは落ち、
    カーネルは生き残る（異常終了メッセージが親へ届く）
