- 依存: §1.1 / §1.3 / §1.4 / §1.5（すべて完了）
- 参照: **詳細 E1**（11 マネージャの分類）/ E22（1 プロセス 1 サーバ）/ 規律 R11

  `src/subsystems/mgr/manager.c` ＋ `src/subsystems/font/fontman.c`
- **マネージャがサーバとして成立する経路を通した**

  ```
  プロセス生成 (§1.1)  → マネージャを別プロセスとして立てる
  共有メモリ (§1.5)    → グリフデータを全プロセスから見える所へ置く
  グローバル名 (§1.4)  → "FONTMAN" でポート ID を公開する
  ランデブ (§1.3)      → 要求と返答
  ```

- **フォントマネージャを最初の 1 本に選んだ理由**: 詳細 E1 が
  「グリフデータは読み出し専用共有メモリ、登録操作だけサーバ」と整理して
  いて、呼び出し粒度が**極細**（DP が文字ごとに呼ぶ）だから。
  利用側は 1 度だけ置き場を教わり、以後は共有メモリを直接読む。
  §1.5 の共有メモリが上位半分（全プロセス共通）にあるので、
  **アドレスをそのまま渡せる**のが効いている
- **受入条件**（すべて通過）
  - グローバル名で見つかる / 見つからなければ `ER_NOEXS`
  - 共有グリフデータが**負のアドレス**にある（§1.5.1）
  - 共有メモリ経由と IPC 経由で**同じアドレス・同じ幅**が返る
  - サーバを止めるとポートとグローバル名が一緒に消える
- **残り**: 各マネージャの本来の API（`wopn_wnd` / `fget_img` …）は
  ディスプレイプリミティブ（第2章）と実身/仮身 (§1.6) 待ち

#### 残り: §1.5.4 のライブラリ

`malloc` / `calloc` / `realloc` / `free`（非常駐ローカル・`DELEXIT`）、
`Smalloc` 系（共有）、`Kmalloc` 系（常駐システム）は**ライブラリ**であって
システムコールではない。仕様自身が「基本的にはブロック単位でメモリを
割り当てる機能のみを OS は提供する。さらに細かく内部を分割するのは
ライブラリ、またはアプリケーション自身で行う」と書いている。

置き場は `src/lib/std/`（LGPL。規律 R14 により `src/kernel` を include
しない）。**ユーザランドの実行環境（EL0 / プログラムの読み込み）が
できてからにする** — いま書いてもリンクする先と動かす場所が無く、
検査もできない。T1-14（タスク例外）と同じ理由で後に回す。
