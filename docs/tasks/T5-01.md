**ドラッグは専用の描画環境で描く。** 影は作業領域をはみ出すので、
ウィンドウの描画環境では描けない。仕様 §3.1.2.5 が `wsta_drg` を
用意していて、元のウィンドウと違うのは「フレーム長方形＝画面全体」
「表示長方形＝元の作業領域」「前置長方形リスト＝元と同じ」の 3 点だけ。
**座標系は同じ**なので影の座標を計算し直さなくてよい。

**切換イベントの読み違いを直した。** 仕様 §3.1.2.2 は

  「位置コードの場合は、PD の**プレス**により入力受付状態の切換えが
    発生したことを意味し、プレスした位置の位置コードが入っている」
  「このイベントを取り出した時点では、**既に**入力受付状態は
    切り換わっており」

と言っている。実装はリリースでも切換イベントにし、cmd に `W_SWITCH` を
入れ、切換をアプリに任せていた。リリースで切り換わると、ドラッグして
別の窓で手を離しただけで入力受付状態が飛んでいく。

- **前置長方形リストが鍵だった。** これが無いと奥のウィンドウが描画する
  たびに手前が消える。仕様が DP 側にこれを用意しているのは、まさに
  ウィンドウマネージャのためである
- **受入条件**（すべて通過。153/153）
  - 生成すると入力受付状態になり、`r` に作業領域の相対座標が返ること
  - 2 枚目を開くと入力受付状態が移り、1 枚目へ `EV_INACT` が届くこと
  - 前面ウィンドウが常に最前面にいて、入力受付状態を変えないこと
  - **手前のウィンドウが奥の描画で上書きされない**こと（画素で確認）
  - 位置コード（作業領域 / タイトル / バー / ハンドル）の判定
  - 入力受付状態でないウィンドウを押すと `EV_SWITCH` になること
  - パネルが入力受付状態を横取りし、閉じると元に戻ること
