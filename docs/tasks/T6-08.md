## この土台へ移すときに変えたところ

- **区画を切る部分は移していない。** T3-03 が既に 2 区画を作っており
  （`--fs-size` もある）、二重実装になる。**残したのは検査と手順だけ**
- 検査の位置づけを書き直した。レーンは「中心核はまだ区画表を読まないので、
  確かめられるのは作った場所しかない」と書いていたが、この土台では起動列が
  タイプ GUID で区画を見つける。**それでも作った場所で確かめる価値はある** —
  媒体の作り方が壊れていると症状はカーネル側に「区画が見つからない」として
  出るので、原因がイメージ側かカーネル側か分からなくなる
- 区画の名前を定数 (`ESP_NAME` / `BTRON_FS_NAME`) にした。作る側 (`sgdisk`)
  と確かめる側が同じ値を見るようにするため（2 か所に書くと必ずずれる）

## 逆検査（それぞれ対応する検査だけが落ちることを確認した）

| 壊し方 | 出たメッセージ |
|---|---|
| 区画 2 に 1 バイト書く | 区画 2 に何か書かれています（空のはず） |
| タイプ GUID を ESP のものに差し替える | 区画 2 のタイプ GUID が違います |
| 開始 LBA を区画 1 の中へ動かす | 区画 2 が手前の区画（または GPT）と重なっています |
| 区画名を変える | 区画 2 の名前が「BOGUS FS」です（「BTRON FS」のはず） |
| **ESP の先頭を消す** | **ESP に FAT の署名 (0x55AA) がありません** |

## 検査を 1 つ足した理由（移植中に実際に踏んだ）

**GPT だけ見ていると「区画は正しいが中身が無い」を通してしまう。**
移植の途中で `mkimage.py` が例外で落ち、**GPT は書けていて ESP だけが空の
イメージ**が残った。ファームウェアの言い分は

```
BdsDxe: No bootable option or device was found.
```

だけで、イメージが悪いのかローダが悪いのかカーネルが悪いのか分からない。
区画表は `sgdisk -p` で見ても正しく、原因に辿り着くのに時間がかかった。
**ESP に FAT の署名があること**を検査に足した（レーンの元の形には無い）。
あわせて、検査を呼ぶ位置を「GPT を書いた直後」から「ESP を流し込んだ後」へ
移した —— **確かめるのは出来上がった物**でなければ意味がない。
