# W0-1 検査を区分ごとのファイルに分ける

- **状態**: 完了
- **委譲**: ✗

- 依存: なし
- 参照: **docs/parallel.md**（並列作業の前提）/ 規律 R29
- 触った: `src/kernel/core/selftest.c`（7,524 → 136 行）＋
  `src/kernel/core/tests/`（区分 23 件 ＋ `common.c` ＋ `testrun.c` ＋
  `testsuite.h`）＋ `src/boot/arm64/kernel.ld` ＋ `CMakeLists.txt`

**なぜやったか。** 検査は 1 つの `selftest.c` に書き足し続けていて
7,500 行になっていた。1 タスク 1 コミットで進めると、**どの作業も必ず
このファイルの末尾を触る**。実際、直近 6 コミットは全部ここを触っている。
並列に進めると全員がそこでぶつかる。

**登録はリンカのセクションに集めた**（`btron_tests`）。区分を足すときに
触るのは自分の新しいファイルだけで、既存のファイルも `CMakeLists.txt` も
1 行も変わらない（ソースは `file(GLOB CONFIGURE_DEPENDS)` で拾う）。

**実行順は order で決める。** リンク順に任せると、ビルドの都合で検査の
順番が変わる。検査には順番に意味があるものがある（フォントマネージャを
立ててから止める、ファイルシステムを接続してから切り離す）。
order の帯は `docs/registry.md` で予約する。

- **受入条件**（すべて通過）
  - 分割の前後で `[ DONE ] 174/174`。9 構成すべてで同じ数
  - 区分が 1 件も登録されていないときは**失敗として報告する**
    （セクションを拾い忘れると検査が 0 件で静かに通る）
  - 新しい区分のファイルを足すのに既存ファイルの変更が要らないこと
