- **委譲**: ○

- 参照: **詳細 E24** / **規律 R18** / Phase 1 ㉘㉙
- `src/kernel/screen/panic.c`。`hal_exception_report()` の先頭で
  `screen_panic_begin()` を呼ぶと、以後の出力が緊急画面に流れる
- **わざと例外を起こす検査** `panic-screen-arm64` で実機の経路を通している。
  ESP に `\BTRON\PANICTEST` を置くと、カーネルもローダも**同じバイナリの
  まま**その経路に入る（フォントを含むカーネルの再ビルドを避けるため）
- **当初の受入条件**
- 参照: **詳細 E24** / **規律 R18** / `BootInfo.fb`
- やること: カーネル常駐。`hal_exception_report` の内容を
  フレームバッファにも出す。**WM の協力を必要としないこと**が要件
- **受入条件**
  - フレームバッファの写像がカーネルの上位半分から外れないこと（R18）
  - 画面に書いた後、**カーネル自身が画素を読み返して検査**する形にすること
    （スクリーンショット比較を避ける。CI に乗る）
  - `-device ramfb` 構成で `[ PASS ] 緊急画面`。
    フレームバッファが無い構成でも落ちないこと
