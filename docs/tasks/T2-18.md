**ディレクトリは無い。** 仕様 §1.6.1 の
「ファイルに含まれるリンク ( 仮身 ) による任意のネットワーク状の参照関係
( 従来のファイルシステムにおけるディレクトリは存在しない )」がすべてで、

  - ファイル（実身）は「可変長レコードの順序列」でバイト列ではない
  - リンク（仮身）は**ファイルの中の 1 レコード**。だから参照関係は網になる
  - ファイル名は一意でない。同名のときは**出現順**（`名前：2`）で区別する
  - 削除は参照カウントが支配する。ルートは最初から 1 で消せない

**ディスク形式は本OS 独自。** 仕様が「物理構造やデータ構造はインプリメント
に依存する」と明言しており、規定があるのは交換用フロッピーだけ（T3-01）。
スーパーブロック / ビットマップ / ファイルインデックス / ブロック連鎖の
素直な配置にした。構造体を直接 I/O せず、バイト単位で詰める（規律 R1）。

**開いている間はレコードストリームをメモリに持つ。** 挿入・削除が日常的に
起きるので、ブロック連鎖の上で直接やると 1 レコードごとに後ろ全部を
書き直すことになる。写しは「システム全体のオープン」ごとに 1 つで、
同じファイルを複数の fd が開いても共有する。仕様が `syn_fls` と
`FS_ASYN` を持っているのは、書き込みが遅れうることを認めているから。

**現在レコードは番号ではなく「そのレコード」。** 仕様 §1.6.3
「現在レコードはレコードの挿入 / 削除によっても変化せず、現在レコードに
対応するレコード番号が変化する」。だから挿入・削除のたびに、同じファイルを
開いている他の fd の番号をずらす。
