# T4-11 描画の走査線化とちらつきの除去

- **状態**: 完了（全画面塗り 238ms → 11.5ms。ポインタ・ウィンドウ移動・状態行の二度書きを解消）
- **委譲**: ○

- 依存: T4-10（DP 本体）・T5-04（外殻が EL0 に居ること）
- 触った: `src/lib/dp/{pixel,draw,bitmap,text,pointer}.c` ＋
  `src/subsystems/window/winman.c`（`expose`）＋
  `src/subsystems/window/demo.c`（状態行）

**遅さがそのままちらつきだった。** 800x600 の全画面を 1 回塗るのに
**238ms** かかっていた。塗っている途中を画面の走査が追い越すので、
書き替えが「流れる」「ちらつく」形で見えていた。

**原因は写像属性ではなく経路だった。** 最初はフレームバッファの写像属性
（Device-nGnRnE か、通常メモリ・キャッシュ無効か）を疑って `MAIR` に
索引を足し `hal_vm_map_framebuf()` を入れた。これは実機では正しいが、
**測ったら 238ms 対 252ms で 6% しか動かなかった**。QEMU ではどちらも
ホストのメモリ操作になるので差が出にくい。本当の支配項は
`dp_plot` を 1 画素ずつ呼ぶ経路で、1 画素あたりクリップ判定・前置長方形の
走査・行頭アドレスの計算・読み出し・マスク判定を全部やり直していた。
48 万画素なら 48 万回である。

**走査線ごとに判定をまとめた。** 1 本の走査線について

1. パターンを**横 1 周期だけ**解く（`dp_pat_row`。周期は標準パターンなら 8）
2. 前置長方形で切った区間を求める（`dp_next_run`）
3. 区間の中は判定が要らないので素直な代入で書く（`dp_run` / `dp_copy_run`）

とした。内側のループは添字の加算と代入だけになる。**11.5ms（20 倍）。**
`gfil_rec` / `gfra_rec` / `gcop_bmp` / `gscr_rec`、それに字形（行ごとに
色が続く区間へ分解）が同じ道具を使う。上書き (`G_STORE`)・マスクピクセル
指定なし・境界ビット数がバイトの整数倍のときだけで、それ以外は従来どおり
1 画素ずつに落ちる。

**「消してから描く」をやめた。** 速さとは別に、同じ点を 2 回書くと
その間が見える。3 箇所を 1 回で書く形に直した。

- **ポインタ**（`src/lib/dp/pointer.c`）: 移動先の下地を先に組み立て、
  古い位置のうち新しい位置で書かない点だけ戻してから、新しい位置を書く。
  重なりの中の下地は画面から読めない（ポインタが写っている）ので
  退避してあるものを使う。そのため下地の器が 2 面要る
- **ウィンドウの移動**（`winman.c` の `expose`）: 元の場所を背景で塗る
  とき、**新しい位置を前置長方形リストで除く**。そこはこの直後に
  ウィンドウ自身が描くので、一度デスクトップ柄にしてから描き直すと
  ドラッグのたびに柄が透けて見える
- **状態行**（`demo.c`）: 白で消してから文字を書くのをやめ、文字の背景を
  不透明にして**文字が覆わない余りだけ**を消す

- **既知の制限**
  - 二重緩衝（裏画面に描いて一度に送る）はまだ入れていない。
    アプリが作業領域を消してから描き直す形は残る。`gopn_mem` ＋
    `gcop_bmp` で組めるようになっている（転送も走査線単位なので速い）
  - 64 ビット単位の書き込み（1 命令で 2 画素）はまだ。実機で効くはず
  - **「1 点を 1 回しか書かない」こと自体は外から観測できない。**
    検査できるのは結果の絵だけである（消し残し・消し過ぎは絵に出る）
- **受入条件**（すべて通過）
  - 全画面塗りが 40ms 未満（実測 11.5ms。1 画素ずつに戻すと 238ms で落ちる）
  - **走査線単位で塗った絵と 1 画素ずつ塗った絵が一致する**
    （前置長方形 0 個 / 1 個 / 2 個の 3 通り）
  - 前置長方形を跨ぐ転送で手前が上書きされない
  - 不透明な背景の字形が文字枠からはみ出さず、枠の中に下地を残さない
  - ポインタの重なる移動・斜めの移動で下地が正しく残る
