# T5-03 ウィンドウマネージャのサーバ化

- 依存: T5-02（外殻のユーザランド化の土台）・§1.3 / §1.4

詳細 E22「1 プロセス 1 サーバ」。仕様 §3.1 の 42 本はすべて利用側の
スタブになり、ランデブでサーバへ届く。アプリから見える関数の形は
仕様どおりのままで、サーバ呼び出しであることは隠れている（規律 R11）。

**描画環境は利用側が持つ。** `wget_gid` が返すのは**呼んだプロセスの中で
有効な GID** である。DP はプロセスごとのライブラリ（詳細 E1）なので、
サーバの GID を渡しても使えない。サーバは「作業領域の絶対座標」と
「手前にあるウィンドウの矩形」だけを返し（`WF_get_env`）、環境は利用側が
組み立てる。前後関係が変わるとサーバの世代番号が進むので、それを見て
組み直す。**この組み立てが前置長方形リストを張る**ので、世代を見落とすと
奥のウィンドウが手前を消す。

**要求元はランデブの記録から引く** (`rdv_caller`)。呼出側に名乗らせると
偽れるし、`prc_self()` で代用するとサーバ自身のプロセスが全ウィンドウの
持ち主になってしまう。**後者は「検査タスクと同じプロセスから呼んでいる
限り区別がつかない」**ので、別プロセスからウィンドウを開く検査を足した。

**待つのは利用側。** `wget_evt` を `W_WAIT` で呼ばれてもサーバは待たない。
待つと、その間ほかのアプリケーションの要求が一切通らなくなる。

- **既知の制限**
  - サーバはまだカーネル内のプロセスのタスク。EL0 へ移すのは次
  - ドラッグ中はサーバがその中で回るので、他の要求が待たされる
- **受入条件**（すべて通過）
  - グローバル名 `WINMAN` で見つかり、要求を直に投げても答える
  - 知らない要求番号は `EX_NOSPT`
  - 別プロセスが開いたウィンドウは**こちらから動かせない / 閉じられない**
  - そのプロセスが終わるとウィンドウも片付く
  - 世代番号を進めないと「手前は上書きされない」が落ちる
