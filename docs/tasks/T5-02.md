詳細 E22「1 プロセス 1 サーバ」のとおり、外殻はユーザランドのプロセスで
あるべきもの。そこへ移せることを、実際に動く外殻の最小形で確かめた。

**描画はシステムコールにしない。** 詳細 E1 が DP を「極めて細かい
呼び出し粒度・グローバルな可変状態なし」としてライブラリに分類している
のがここで効く。ユーザプログラムは `src/lib/dp/*` を結合し、
特権境界を越えるのは

  1. 画面を借りるとき（1 度だけ）
  2. フォントマネージャの置き場を引くとき（1 度だけ）
  3. イベントを取り出すとき

の 3 か所だけになる。`env.c` に「EL0 を作ったらここが下位半分への写像に
変わる」と書いてあったとおりになった。

**ランデブがアドレス空間をまたげなかった。** 呼出側と受付側のバッファを
ポインタで渡していたので、両者が別のアドレス空間に入った瞬間に壊れる。
複写が「呼出側の文脈」と「受付側の文脈」のどちらで起きるかは状況次第
なので、どちらの番地も安全ではない。TCB にカーネル側の中継を置き、
各々が自分の文脈で出し入れするようにした。
