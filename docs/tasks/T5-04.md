# T5-04 ウィンドウマネージャを EL0 へ

- **状態**: 完了（カーネルには利用側だけが残る）
- **委譲**: △

- 依存: T5-03（サーバ化）・T2-19 EL0・T2-20 cre_prc
- 触った: `src/user/winman_main.c`（WM の MAIN）＋
  `src/subsystems/window/winboot.c`（起こす側）＋
  `prc_create_obj`（埋め込みから起こす口）＋ `rdv_caller` のシステムコール

**カーネルには利用側 (`wincli.c`) だけが残る。** `winman.c` と
`winsrv.c` はユーザプログラムに結合され、保護されたユーザ特権で走る
1 つのプロセスになった。これが詳細 E22「1 プロセス 1 サーバ」の形である。

**ファイルを通さずに起こす。** 仕様の `cre_prc` は実身から読むが、
外殻のサーバはファイルシステムが立つより先に起きていなければならない
（画面が無ければ何も見えない）。実行プログラムレコードをカーネルへ
埋め込み、`prc_create_obj` で直接起こす。ファイルから起こす経路
（`cre_prc`）も検査で別に通してある。

**プロセス終了の知らせが来なくなる。** カーネル内に居たときは
`win_release_process` が呼ばれてウィンドウが片付いた。外へ出るとその口が
無いので、サーバが要求を処理する**前に**持ち主の生死を見て片付ける。
後に回すと、持ち主が死んだ直後の 1 回目の問い合わせに古い答えを返す。

**ポート ID を覚えてはいけない。** ID は使い回されるので、覚えたままだと
サーバを立て直したあと**別のサーバのポートに話しかけてしまう**。誰も
受け付けていなければ永久に待つし、別のサーバが受け付ければでたらめな
答えが返る。毎回グローバル名から引く（`get_nam` 1 回なので安い）。

- **既知の制限**
  - ドラッグ中はサーバがその中で回るので、他の要求が待たされる。
    仕様が想定する形（詳細 E1 の `rcv_msg(WAIEVT)` + `brk_msg`）に
    寄せるときに直す
  - フォントマネージャはまだカーネル内（字形データがそこにある）
- **受入条件**（すべて通過）
  - 「[WM] ユーザ特権で起動しました」が出る
  - ウィンドウマネージャが**呼び出し側と別のプロセス**である
  - サーバを終わらせ、起こし直し、また窓が開ける
  - 持ち主のプロセスが終わるとウィンドウも片付く
