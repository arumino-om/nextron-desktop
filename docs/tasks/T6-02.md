# T6-02 実機で死なない経路（R31 / F7）

- **状態**: **完了** — 両アーキ。逆テスト 2 構成（`no-uart` / `poweroff-psci`）付き
- **委譲**: ◎

- 依存: なし
- 参照: 規律 **R31** / R19 / **詳細 F9** の「実機で初めて効く差」/ F7
- **なぜ先にやるか**: いまのカーネルは実機で 2 か所、無言で止まる。
  `src/kernel/hal/arm64/uart.c` は記述が読めないと **QEMU の PL011 の番地
  (0x0900_0000) へ書き続ける**（実機では外部アボート）。`hal_exit` は ARM
  セミホスティングで、実機では命令自体が例外になる。**この 2 つを直さないと、
  実機で何が起きても分からない。**
- やること
  - **シリアルは黙った状態から始める。** 開ける道を 2 つに限る —
    記述が指した番地か、**ID / スクラッチレジスタで確かめた既定値**だけ（R31）。
    開けなければ黙り、出力は画面が引き受ける（`hal_console_tee` と緊急画面）
  - x86_64 の 16550 は**居ない装置の THRE を待って永久に回る**形なので直す
  - `hal_exit` を 3 段にする — セミホスティング → 記述どおりの電源断
    （arm64 = PSCI SYSTEM_OFF / x86_64 = ACPI S5）→ 停止ループ。
    セミホスティングを先に試すのは**終了コードを持ち帰れるのがそれだけ**だから
  - シリアルが黙っている構成では**電源を落とさず画面に残して止まる**
- **受入条件**
  - 既存の全構成が通り続ける
  - **UART を意図的に落とした構成**で、黙って先へ進み、画面に `[ PASS ]` が出る
    （逆テストはその検査が走る構成で回す。R27）
  - PSCI SYSTEM_OFF 経由で QEMU が終了する構成がある
  - 既定アドレスへ無条件に書き込む経路が残っていないこと

- 触った: `include/btron/hal.h`（`hal_console_default` / `hal_console_opened` /
  `hal_cpu_halt` を追加、`hal_console_init` を削除）＋
  `include/btron/{bootinfo,machdesc,screen}.h` ＋
  `src/boot/{arm64,x86_64}/boot.c`（**順序の入れ替えが本体**）＋
  `src/boot/uefi/main.c`（NOUART の印）＋ `src/kernel/boot/{acpi,machdesc,bootlog,earlytest}.c` ＋
  `src/kernel/hal/{arm64,x86_64}/{uart,exit,cpu}.c` ＋ `src/kernel/screen/console.c` ＋
  `tools/{mkimage,run_qemu}.py` ＋ `CMakeLists.txt`

## この土台へ移すときに変えたところ

- 規律の番号を **R29 → R31**（この土台の R29 は「並列作業が同じファイルを
  触る形にしてはならない」で別物）。判明は **(62)〜(65)**（T6-01 が (57)〜(61)）
- `BI_F_NO_UART` のビットを **0x0004 → 0x0008** に移した。T3-03 の
  `BI_F_SELFBOOT` が 0x0004 を使っており、**同じ値を別の意味で取っていた**
  （registry.md の §7 に BootInfo のフラグを登録して再発を止めた）
- **`hal_console_pa()` を 2 つの問いに分けた。** T1-11 は「MMIO 区画に張る
  べき番地」として 0 を期待し（x86 のポート I/O はアドレス空間に現れない）、
  T6-02 は「黙っているか」の判定に使っていた。PIO のアーキでは必ず食い違う
  ので、`hal_console_opened()` を新設して意味を 1 つずつにした
- 起動時の表示は `bootlog.c`、起動時の検査は `earlytest.c` へ（T1-11 が
  `boot.c` から切り出してある）
- **NOUART の印が立っているときは既定値も試さない**ようにした。x86 は
  記述に SPCR が無くても COM1 を確かめて開くので、印だけでは黙らない
- R31 の検査を**アーキで分けた** — 分かれ目は「確かめること自体が落ちるか」。
  MMIO (arm64) は居ない番地を**読むだけで外部アボート**なので触らない。
  PIO (x86) は突いても止まらないのでスクラッチレジスタで確かめて開ける
- `no-uart` の検査を **両アーキで走るようにした**（arm64 の囲みの外へ出した）。
  シリアルが無い機械はむしろ x86 のノート PC の話なので
