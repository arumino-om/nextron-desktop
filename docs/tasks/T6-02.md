# T6-02 実機で死なない経路（R31 / F7）

- **状態**: 未着手
- **委譲**: ◎

- 依存: なし
- 参照: 規律 **R31** / R19 / **詳細 F9** の「実機で初めて効く差」/ F7
- **なぜ先にやるか**: いまのカーネルは実機で 2 か所、無言で止まる。
  `src/kernel/hal/arm64/uart.c` は記述が読めないと **QEMU の PL011 の番地
  (0x0900_0000) へ書き続ける**（実機では外部アボート）。`hal_exit` は ARM
  セミホスティングで、実機では命令自体が例外になる。**この 2 つを直さないと、
  実機で何が起きても分からない。**
- やること
  - **シリアルは黙った状態から始める。** 開ける道を 2 つに限る —
    記述が指した番地か、**ID / スクラッチレジスタで確かめた既定値**だけ（R31）。
    開けなければ黙り、出力は画面が引き受ける（`hal_console_tee` と緊急画面）
  - x86_64 の 16550 は**居ない装置の THRE を待って永久に回る**形なので直す
  - `hal_exit` を 3 段にする — セミホスティング → 記述どおりの電源断
    （arm64 = PSCI SYSTEM_OFF / x86_64 = ACPI S5）→ 停止ループ。
    セミホスティングを先に試すのは**終了コードを持ち帰れるのがそれだけ**だから
  - シリアルが黙っている構成では**電源を落とさず画面に残して止まる**
- **受入条件**
  - 既存の全構成が通り続ける
  - **UART を意図的に落とした構成**で、黙って先へ進み、画面に `[ PASS ]` が出る
    （逆テストはその検査が走る構成で回す。R27）
  - PSCI SYSTEM_OFF 経由で QEMU が終了する構成がある
  - 既定アドレスへ無条件に書き込む経路が残っていないこと
