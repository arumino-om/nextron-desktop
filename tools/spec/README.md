# 仕様文書の資産化ツール

BTRON3 仕様書 / 超漢字 (B-right/V R4) 仕様書を、実装に使える形に変換する。

## 前提

**仕様文書そのものはリポジトリに含まれない。** 著作権者が別にあるため
(`docs/design-issues.md` §1 ライセンス方針)。各自がローカルに置いたものを使う。

探索順:

1. 環境変数 `BTRON_DOC` / `BRIGHTV_DOC`
2. リポジトリルート直下
3. git worktree の本体チェックアウト直下
4. `~/Downloads` 直下

どれを使ったかは実行時に表示される。

## 使い方

```sh
nix develop

python3 tools/spec/html2text.py     # HTML(EUC-JP) -> UTF-8 テキスト
python3 tools/spec/figures.py       # 図版 GIF -> PNG (拡大)
python3 tools/spec/extract_api.py   # API 一覧の抽出
```

## 出力先

| 出力 | 場所 | コミット |
|---|---|---|
| テキスト化した仕様本文 | `.spec-work/text/` | **しない**（原文を含むため） |
| 拡大した図版 | `.spec-work/fig/` | **しない**（原文を含むため） |
| API 一覧・定数一覧 | `docs/api/` | **する**（インタフェースの事実） |

この区別が §1 の「守る線」3.「仕様から抽出した事実はコミットしてよい、
解説文の長い貼り付けはしない」に対応する。

## 図版について

仕様書の図版にはビット配置など**本文にない情報**が含まれる。たとえば

- 図70 レコードインデックスの 16 バイト構成（4 形式の判別と各フィールド）
- 図67 ファイルヘッダの byte offset
- 図58 システムヘッダの byte offset
- 図53 ウィンドウの属性
- 図3 プロセスの状態ワード

原寸の GIF は小さくて読めないので `figures.py` で拡大する。線画なので
最近傍 (point) 補間を使い、拡大しても罫線と文字がボケないようにしている。

## 既知の限界

- **中心核 (BV 第5編) のシグネチャは抽出できない。** この編は
  μITRON3.0 標準ハンドブック (ISBN4-89362-154-8) との**差分**であり、
  完全な API 定義は仕様書に含まれない。`extract_api.py` は名前と概要だけを拾う。
- 開発ツール (BMS / IMS / CLI) は C の API ではなくコマンドリファレンスなので
  抽出対象から除外している。
